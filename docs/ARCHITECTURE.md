# Архитектура: симулятор аппарата ИВЛ и монитора пациента

Целевая архитектура. Текущий код (один `index.html` на чистом JS) переводится на неё поэтапно,
см. раздел «Этапы».

## 1. Устройства и ответственность

На занятии три устройства, связанные кодом сессии:

| Устройство | Отвечает за | Не делает |
|---|---|---|
| **Пульт инструктора** | Все параметры пациента и физиологию (газообмен, гемодинамика, дыхательный центр), сценарий, ошибки, журнал, зеркала аппарата и монитора | Не рисует кривые в реальном времени |
| **Аппарат ИВЛ** | Механику лёгких с шагом 4 мс (параметры C, R, Pmus задаёт пульт), режимы, измерения аппарата, свои пределы и тревоги | Не считает SpO₂/CO₂, а показывает значения с пульта |
| **Монитор пациента** | Синтез и отрисовку кривых (ЭКГ, плетизмограмма, капнограмма), НИАД, свои пределы и тревоги | Не считает физиологию |

Главный принцип: **у каждого числа один владелец**. Механику лёгких аппарат обязан считать сам
(250 Гц по сети не передать), но её параметры приходят с пульта.

```
           v: FiO₂, PEEP, Pmean, MV, VTE, f, fSpont, ожидание
  Аппарат ─────────────────────────────────────────────► Пульт
     ▲   i: C, R, Pmus, утечка, ошибки, SpO₂/EtCO₂          │ физиология раз в 1 с
     └─────────────────────────────────────────────────────┤
     │  b: события вдоха и выдоха                          │ ph: ЧСС, ритм, АД, SpO₂,
     ▼                                                     ▼     EtCO₂, ЧД, t°, перфузия
  Монитор ◄────────────────────────────────────────────────┘
     └──── m: тревоги, НИАД, действия ──────────────────► Пульт (зеркало, журнал)
```

### Без пульта
Аппарат и монитор держат последние полученные значения и показывают «Нет связи с пультом».
Отдельной физиологии на аппарате нет: две модели разошлись бы.

### Пульт уходит в фон (iPad/Safari останавливает JS)
- Wake Lock API: экран не гаснет (Safari 16.4+).
- Физиология шагает по реальному прошедшему времени и после возврата догоняет.
- Всё состояние пульта (пациент, ошибки, сценарий, время сценария) сохраняется
  в localStorage и восстанавливается после перезагрузки. Перезагрузка пульта
  не должна снимать ошибки на аппарате.

## 2. Технологии

- **TypeScript + React + Vite.** Сборка в **один самодостаточный `index.html`**
  (`vite-plugin-singlefile`): страницу по-прежнему можно опубликовать артефактом на claude.ai,
  залить на любой хостинг и отдать через `server.py`.
- Собранный `index.html` **коммитится в корень репозитория**. Чтобы запустить сервер
  (start-mac.command, Docker, a-Shell на iPad), Node не нужен; Node нужен только разработчику.
- `server.py` остаётся на голом Python без зависимостей.
- Тяжёлые части не трогают React. Шаг модели (4 мс) и отрисовка кривых на canvas работают
  в своём цикле `requestAnimationFrame`. React перерисовывает числа и панели не чаще 2–4 раз в секунду
  через `useSyncExternalStore`.
- mqtt.js не входит в сборку: он подгружается с unpkg/jsdelivr, только когда нужен этот канал.
- Тесты: **Vitest** для движка (чистые функции), **Playwright** для e2e на три роли.
- Типы протокола и модели на TypeScript пишутся так, чтобы переноситься на Swift
  один к одному: структуры без классов с поведением, функции «состояние → состояние».

## 4. Модель пациента (на пульте)

Инструктор задаёт **свойства** пациента, показатели получаются из них. У каждого выходного
показателя есть режим «Авто» (считает модель) и «Ручной» (целевое значение плюс время перехода,
например «SpO₂ 82% за 60 с»). Подмена fTotal/VTE на аппарате — частный случай ручного режима.

| Группа | Входы (задаёт инструктор) | Выходы |
|---|---|---|
| Механика | C, R, утечка % | (считает аппарат) |
| Дыхательный центр | седация, базовые ЧД и усилие, «драйв от PaCO₂» вкл/выкл | Pmus: частота, амплитуда |
| Оксигенация | шунт %, рекрутируемость, запас O₂ (ФОЕ) | PaO₂, SpO₂ |
| Вентиляция | VCO₂, Vd/Vt | PaCO₂, EtCO₂ |
| Гемодинамика | ритм, базовые ЧСС и АД, гиповолемия, «автоухудшение» вкл/выкл | ЧСС, САД/ДАД/СрАД, перфузия |
| Прочее | температура | t° |

Упрощения (намеренные; при изменениях описывать в коммите):

- **O₂.** PAO₂ = FiO₂·(Pатм − 47) − PaCO₂/0,8. Эффективный шунт = шунт·(1 − рекрутируемость·k(PEEP)).
  SaO₂ — смесь капиллярной сатурации (из PAO₂ по кривой Северингхауса) и венозной (≈ 70%)
  в долях шунта. SpO₂ следует за SaO₂ с постоянной ≈ 20–30 с.
  При отключении или апноэ SpO₂ держится, пока не исчерпан запас O₂ (зависит от FiO₂ до апноэ),
  потом падает. Так видна польза преоксигенации.
- **CO₂.** VA = (VTE − Vd)·f; равновесное PaCO₂ = 0,863·VCO₂/VA, приближение с постоянной ≈ 2–3 мин;
  при апноэ рост 3–6 мм рт. ст./мин. EtCO₂ = PaCO₂ − градиент (растёт с Vd/Vt);
  при отключении EtCO₂ = 0.
- **Гемодинамика.** ЧСС растёт при гипоксии и гиперкапнии; при глубокой гипоксии,
  если включено автоухудшение, — брадикардия. СрАД падает с Pmean пропорционально гиповолемии.
- **Дыхательный центр.** Спонтанные ЧД и усилие растут с PaCO₂ и падают с седацией;
  при гипервентиляции — апноэ.
- **Ускорение времени** ×1…×10, чтобы медленные эффекты были видны на занятии.

## 5. Монитор пациента (версия 1)

- **ЭКГ**: одно отведение. Ритмы: синусовый, синусовые тахикардия и брадикардия, ФП, СВТ, ЖТ, ФЖ, асистолия;
  опция «ЖЭС». ЧСС по ЭКГ.
- **SpO₂** + плетизмограмма; амплитуда — от перфузии.
- **EtCO₂** + капнограмма по событиям вдоха `b` с аппарата; ЧД по капнограмме.
- **НИАД**: по кнопке и по циклу (2,5–60 мин); замер длится ≈ 30 с, значение берётся из физиологии
  в конце замера.
- **Температура.**
- Пределы и тревоги монитора — свои, общие с пультом (так же, как у аппарата).
- Ошибки монитора с пульта: электроды отключены, датчик SpO₂ снят, артефакт движения,
  манжета не накачивается.
- В версии 1 нет дефибриллятора, СЛР, инвазивного АД и ЦВД.

## 6. Протокол (версия 2)

Сообщения передают абсолютное состояние, а не изменения. Конверт: `{from, t, d}`, в `d` есть поле `pv: 2`.
Лимит сообщения ≈ 4 КБ (канал Claude), кириллица занимает 2 байта.

| `t` | Откуда → куда | Частота | Содержимое |
|---|---|---|---|
| `v` | аппарат → все | 1 Гц + при изменениях | режим, настройки, ожидание, IBW, мониторинг, тревоги (до 10), пределы, последние записи журнала, входы физиологии (FiO₂, PEEP, Pmean, MV, VTE, f, fSpont) |
| `i` | пульт → аппарат | 1 Гц | механика (C, R, утечка), Pmus (ЧД, усилие), ошибки аппарата, свои тревоги, подмены, SpO₂/EtCO₂ для экрана аппарата, пределы аппарата |
| `ph` | пульт → монитор | 1 Гц | ЧСС, ритм, ЖЭС, АД, SpO₂, перфузия, EtCO₂, PaCO₂ для формы капнограммы, t°, ошибки монитора, пределы монитора |
| `b` | аппарат → монитор | на каждый вдох и выдох | `{ph: 'i'|'e', ts}` |
| `m` | монитор → пульт | 1 Гц | показатели на экране, тревоги, последнее НИАД, пределы, последние записи журнала |
| `lim` | любая сторона | при изменении | `{dev: 'vent'|'mon', lim, ts}`; побеждает больший `ts` |
| `log` | аппарат, монитор | при событии | `{id, ts, x, dev}`; пульт склеивает по `id` |

Каналы связи прежние: свой сервер → канал Claude → открытый MQTT → BroadcastChannel.

## 7. Этапы

0. **Каркас.** `web/` на Vite + React + TS, сборка в один `index.html`, перенос текущего аппарата и пульта
   без изменения поведения. Движок вынесен в `engine/` и покрыт тестами (Vitest), e2e на две роли.
1. **Физиология на пульте.** Протокол v2, `physio/` (O₂, CO₂, дыхательный центр), «Авто / Ручной»,
   сохранение состояния пульта, Wake Lock, ускорение времени. SpO₂ и EtCO₂ на аппарате берутся с пульта.
2. **Монитор, версия 1.** Третья роль (раздел 5), зеркало монитора на пульте, e2e на три роли.
3. **Гемодинамика и ритмы** в физиологии, автоухудшение.
4. **Сценарии.** Таймлайн и условия, импорт/экспорт JSON, тренды для дебрифинга.
5. **Режимы ИВЛ:** DuoPAP, APRV, HiFlowO2.
6. **Нативное iOS-приложение** на том же протоколе; `engine/` переносится на Swift.
